# Задание 3. Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

В системе обрабатываются несколько категорий данных

| Класс данных        | Примеры                  | Уровень чувствительности | Профиль риска |
| ------------------- | ------------------------ | ------------------------ | ------------- |
| Public              | маркетинговая информация | низкий                   | низкий        |
| Internal            | служебные данные         | средний                  | средний       |
| Personal Data (PII) | ФИО, телефон, email      | высокий                  | высокий       |
| Medical Data        | диагнозы, анализы        | критический              | критический   |
| Financial Data      | платежи, транзакции      | высокий                  | высокий       |
| Authentication Data | пароли, токены           | критический              | критический   |

## 2. Классификация данных и инструменты защиты

| Данные               | В чём необходимость защиты              | Инструменты защиты            |
| -------------------- | --------------------------------------- | ----------------------------- |
| ФИО пациента         | Персональные данные (152-ФЗ)            | AES-256 шифрование в БД       |
| Телефон пациента     | Возможность утечки контактов            | AES-256 + masking             |
| Email пациента       | Возможность фишинга                     | AES-256                       |
| Паспортные данные    | Идентификация личности                  | AES-256 + restricted access   |
| Медицинские карты    | Медицинская тайна                       | AES-256 + RBAC + аудит        |
| Результаты анализов  | Конфиденциальная медицинская информация | AES-256 + Data Tagging        |
| Платёжные данные     | Финансовые риски                        | Tokenization                  |
| Пароли пользователей | Критическая информация                  | bcrypt / Argon2               |
| JWT токены           | Возможность захвата сессии              | короткое время жизни + TLS    |
| Логи системы         | Могут содержать PII                     | masking + ограниченный доступ |

## 3. Средства автоматизированного контроля

Для обеспечения безопасности данных используется автоматизированный мониторинг

### Audit logging

Все действия записываются:
- доступ к медицинским картам
- изменение данных
- выгрузка данных

Инструменты:
- ELK Stack

### SIEM

Обнаружение аномалий

Примеры:
- массовый доступ к картам пациентов
- доступ вне рабочего времени
- необычные запросы API

Инструменты:
- Wazuh

### Data Loss Prevention (DLP)

Контроль утечки данных

Проверяет:
- email
- выгрузки
- копирование файлов

### Data Governance

Для управления конфиденциальными данными используются

#### Data Tagging

Пример тегов:
- PII
- MEDICAL
- FINANCIAL
- CONFIDENTIAL

#### Access Control

Используются:
- RBAC
- ABAC

#### Data Retention

Политика хранения данных

| Тип данных         | Срок хранения |
| ------------------ | ------------- |
| медицинские данные | 5–10 лет      |
| логи               | 1 год         |
| временные данные   | 30 дней       |

## 4. Реестр программных и аппаратных средств защиты

| Тип                | Инструмент            | Назначение                   |
| ------------------ | --------------------- | ---------------------------- |
| IAM                | Keycloak              | аутентификация и авторизация |
| API Security       | API Gateway           | защита API                   |
| Encryption         | TLS 1.3               | защита передачи данных       |
| DB Encryption      | PostgreSQL Encryption | защита БД                    |
| Secrets            | Hashicorp Vault       | хранение секретов            |
| Monitoring         | ELK Stack             | логирование                  |
| SIEM               | Wazuh                 | анализ безопасности          |
| Container Security | Kubernetes Secrets    | управление ключами           |
| Backup Security    | Encrypted backups     | защита резервных копий       |
| Data Tagging       | Apache Atlas          | разметка данных              |
